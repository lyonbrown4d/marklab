# Electron 启动与资源优化验证

> 历史记录：本页数据与命令对应当时的 Electron 实现。该实现、构建配置和测试入口现已移除；保留原始测量，不作为当前 Tauri 或 Chromium renderer 的验收结果。当前验证范围见[质量检查](../quality-gates.md)。

本轮以 `d67d3ed` 为基线，针对 Electron 官方性能建议中“延后非必要加载”和“避免阻塞主进程”落地六项优化。没有新增运行时依赖、生产调试接口或通用 IPC 能力。

参考：[Electron Performance](https://www.electronjs.org/docs/latest/tutorial/performance)。

## 改动与行为边界

| 范围             | 改动                                                                             | 保留的功能                                                                              |
| ---------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 渲染进程分包     | 移除会把懒加载功能拉入静态入口的宽泛 vendor 分组，按实际导入图分包               | 编辑器、源码、地图、Mermaid、数学公式和 PDF 仍在对应使用路径加载                        |
| 默认工作区初始化 | 构造函数不再同步递归扫描；首次读取或修改前异步准备；同一根目录共享正在进行的准备 | 隐藏目录过滤、已有笔记识别、空工作区创建 Untitled、失败重试、根切换隔离、已有文件不覆盖 |
| AI SDK           | 首次生成时加载生成 SDK，仅加载选定提供方；并发共享加载结果；失败释放缓存         | 每次请求独立模型与凭据、取消检查、提供方策略和错误反馈                                  |
| 文件监听         | 根目录验证及 create 元数据读取改为异步；每批最多 16 个并行 stat，批次按顺序处理  | 事件顺序、自己写入的过滤、切换/关闭后的过期回调抑制                                     |
| 备用窗口         | 未使用的备用窗口保留两分钟后释放；使用、崩溃、关闭时清理定时器                   | 当前工作窗口不受影响、原有内存余量检查、冷启动回退                                      |
| 链接预览缓存     | 初始全量维护延后 30 秒，定时器可取消且不阻止退出                                 | 读取时过期检查、写入后的容量约束、显式维护、六小时周期维护                              |

基线性能采样还暴露了已有的恢复竞态：文件树刷新可能抢先使选择文件路由的恢复任务失效，窗口报告就绪但仍停留在起始页。本轮将恢复期间的树变化合并，在恢复、绘制和就绪报告完成后补一次当前根目录刷新。真实 `useProjectLoader` 与种子恢复的集成测试覆盖了最新种子、根切换、失败恢复和卸载。

## 实际构建的静态依赖

使用生产配置构建后，以 `es-module-lexer` 遍历入口的静态相对导入，按文件去重，累计未压缩 JS 字节；不包含动态导入及 CSS。

| 指标              |                  基线 |                改动后 |        变化 |
| ----------------- | --------------------: | --------------------: | ----------: |
| 渲染入口静态 JS   | 9,620,043 B / 28 文件 |   273,957 B / 22 文件 | 减少 97.15% |
| 主进程入口静态 JS | 5,260,963 B / 14 文件 | 4,320,194 B / 13 文件 | 减少 17.88% |

改动后的主进程静态闭包不包含生成 SDK、SDK 公共工具和四个提供方 SDK。每个提供方的动态依赖闭包也没有引入其他提供方。

渲染入口字节数只描述最初的静态启动链。正常窗口随后还会加载应用和编辑器，因此不能将它解释成完整首篇文档的总下载量、总包大小或内存下降比例。发射依赖图回归测试同时覆盖共享 React、Zod 和 SDK 工具造成的意外静态耦合。

## 文件系统与缓存测量

使用基线与改动后的实际服务源码生成独立模块，在不同的临时目录中准备相同数据；模块加载与夹具构造不计入测量。测试结束删除夹具并释放监听和计时器。

| 场景                                                                  |            基线 |    改动后 | 解释                                        |
| --------------------------------------------------------------------- | --------------: | --------: | ------------------------------------------- |
| 默认目录：800 个可见目录、12,800 个非 Markdown 文件；最大事件循环延迟 |        40.21 ms |   2.56 ms | 同步扫描不再持续占用主线程                  |
| 同一目录扫描总耗时                                                    |        38.95 ms |  74.43 ms | 异步扫描总耗时增加；目标是响应性            |
| 原生 watcher：1,024 个新建文件；最大事件循环延迟                      |        21.58 ms |  23.51 ms | 此样本没有证明速度提升                      |
| 同一 watcher 新建事件全部交付耗时                                     |       175.48 ms | 204.92 ms | 两版都收到 1,024 个唯一事件；保留成本与边界 |
| 1,000 个过期 JPG；开始维护后前 200 ms 的目录读取 / stat / 删除次数    | 1 / 1,000 / 464 | 0 / 0 / 0 | 启动阶段维护 I/O 被延后                     |

显式维护在两版都清理了全部 1,000 个过期缓存。前版已在 200 ms 内完成部分删除，后续清理时长无法直接比较。watcher 测量使用 macOS FSEvents，并对临时目录的符号链接路径做了规范化；没有据此声称 Linux 或 Windows 的性能收益。失败的 4,096 文件原生监听试验保留在本地记录中，没有用于结论。

## 原生应用测量方法

`e2e/performance/startup.performance.spec.ts` 使用两个冻结构建目录、相同 Electron 二进制、隔离 HOME 和用户数据，以及相同原生 GPU 配置顺序执行。每版一轮预热加五轮有效测量，保留所有失败记录；出现任何失败，测试门禁仍会失败。

启动计时从 Electron 启动请求开始，直到 Markdown 编辑器报告 ready。第一个额外工作区在清理初始备用窗口后冷启动；第二个使用准备好的备用窗口，两者均校验实际获取来源。仅在隔离测试进程中把备用窗口资格的可用内存下限固定为 512 MiB，避免宿主系统内存波动使比较混入冷启动；实际内存读数不做改写，生产仍使用真实余量检查。

空闲事件循环观察窗口固定为两秒。内存记录来自 Electron `app.getAppMetrics()` 与渲染进程 CDP；保留缺失字段。比较三个工作窗口加一个备用窗口，与主动删除同一个备用窗口、一秒后采样的差值。这验证备用进程资源成本；两分钟自动释放及已取得窗口不被过期定时器销毁另由假时钟单元测试验证。

这是 macOS arm64 上的生产 JS 构建测量，页面由测试专用 loopback 服务器提供；没有打包、签名或操作系统缓存清空，不能替代正式安装包在各平台的启动基准。五个样本的 p95 是样本最大值，不能据此推断长期分布。

## 原生应用测量结果

两版最终采样均为 6 次尝试：1 次预热、5 次正式样本、0 次失败。全部窗口获取来源及编辑器 ready 校验通过。每个正式启动 RSS 样本均包含 6 个进程，包括初始备用渲染进程。以下 RSS 是各进程驻留内存之和，可能重复计入共享页，不代表唯一物理内存；macOS privateBytes 字段缺失，未当成零。

| 指标                                       |         基线 |      改动后 | 解释                                                   |
| ------------------------------------------ | -----------: | ----------: | ------------------------------------------------------ |
| 启动至编辑器 ready，中位数                 |  2,640.83 ms | 1,828.62 ms | 本机样本减少 30.76%                                    |
| 启动至编辑器 ready，样本 p95               |  2,660.55 ms | 2,273.10 ms | 新版最后一轮偏慢，保留全部样本                         |
| 冷开工作区，中位数                         |     1,199 ms |      994 ms | 减少 17.10%                                            |
| 池化打开工作区，中位数                     |       761 ms |      765 ms | 基本持平；不声称加速                                   |
| ready 时全应用进程 RSS，中位数             | 1,200.77 MiB |  964.61 MiB | 相同进程数下减少 236.16 MiB                            |
| ready 时主进程 RSS，中位数                 |   326.53 MiB |  310.92 MiB | 减少 15.61 MiB                                         |
| 备用渲染进程自身 RSS，中位数               |   258.81 MiB |  138.08 MiB | 懒加载减少未使用功能的启动成本                         |
| 删除备用窗口后全应用 RSS 下降，中位数      |   253.84 MiB |  133.50 MiB | 验证释放一个备用渲染进程的资源效果                     |
| 两秒空闲观察的事件循环 p95，中位数         |     12.21 ms |    12.19 ms | 基本持平，监测分辨率为 10 ms                           |
| 全部空闲观察中最大事件循环延迟             |     13.09 ms |    49.91 ms | 新版最后一轮出现峰值；尚未归因，不声称空闲响应性能改善 |
| 首次应用就绪后记录的 JS 资源请求数，中位数 |          124 |         170 | 自动分包增加小文件数量，作为取舍保留                   |

启动样本变异系数从 0.0068 增至 0.0946。新版 4 轮启动在 1.80–1.88 秒附近，另一轮为 2.27 秒。没有删除该样本，也没有把入口字节下降比例当作运行时收益。探索阶段基线曾出现已有恢复竞态失败，记录保留在 `startup-before.json`；最终正式采样结果单独保存，不覆盖探索记录。

可核对的每轮标量与汇总保存在 [测量数据](./electron-startup-2026-10-13.json)。这些结果支持本机启动和资源成本改善；跨平台收益及空闲延迟峰值仍需要对应环境的持续测量。

复跑示例：

```sh
MARKLAB_PERFORMANCE_BUILD_ROOT=.tmp/performance/electron-2026-10-13/before \
MARKLAB_PERFORMANCE_REPORT_PATH=.tmp/performance/electron-2026-10-13/startup-before-final.json \
node node_modules/@playwright/test/cli.js test \
  -c playwright.performance.config.ts startup.performance.spec.ts --project native-gpu
```

构建目录需要包含 `dist`、`dist-electron`、`resources` 和 `package.json`。用相同方法对 after 目录复跑。只需冒烟时可设置 `MARKLAB_PERFORMANCE_SMOKE=1`，这不提供可靠性能分布。

## 本地证据

完整单元与集成测试通过：843 个文件、4,492 个用例。配置中的关键模块覆盖率门禁通过：语句 97.69%、分支 90.73%、函数 98.98%、行 98.76%。这是关键模块集合的覆盖率，不是整个代码库的覆盖率。本轮新增的异步初始化、根选择、快照缓存、预热、AI/缓存和备用窗口路径还执行了专项覆盖率检查。

31 个不同的真实 Electron 场景通过，覆盖安全 preload、窗口尺寸和弹层、编辑保存/搜索/只读、源码模型隔离、数学/脚注、选区工具栏、工作区历史/失效/删除、默认向导、多窗口恢复、工作区迁移和创建、同步配置入口、地图/长文档/大图交互、拖动透明度、AI 首次生成、Mermaid 和 PDF。AI 原生生成使用本地 OpenAI-compatible 测试服务；其他提供方依赖图、配置、取消和重试由模块测试及审查覆盖，未请求外部收费服务。Draw.io 远程编辑器审计未运行，没有计入通过数。

TypeScript 项目检查、脚本类型检查、改动文件 ESLint/Prettier，以及全库 300 有效行限制检查通过。两处当前工作区重复打开的旧测试预期已改为不打开且关闭菜单，并保留其他工作区打开的断言。焦点交接测试等待选中文档的回调注册后再报告就绪，没有放宽焦点和侧栏断言。

地图几何测试使用单文档临时工作区，避免用户向导的多文档数据破坏夹具假设；长文档由文件夹具提供。空段落 Cmd+A 后 Plate 会进入块选择，`keyboard.insertText` 不发送其需要的 keydown；冻结基线与新构建的原生探针均复现相同行为，不能用该测试输入方式判定此次性能回归。真实按键输入、保存仍由桌面冒烟及编辑旅程覆盖。大地图的总节点数改从代表完整图的小地图读取，因为主画布原本就只渲染可见节点；其余搜索、编辑、拖动、缩放和布局断言保留。

原始结果位于 `.tmp/performance/electron-2026-10-13/`：`bundle-comparison.json`、`workspace-fs-stress.json`、`workspace-fs-methodology.txt`、`cache-measurement.json`、前后原生启动采样及各模块覆盖率摘要。夹具和构建快照不纳入 Git。

并行工作分为渲染分包、AI/缓存、工作区/监听、恢复竞态审查。可用模型清单没有 Spark，使用 `gpt-6.1-sol` 作为回退；竞态、实际依赖图和文件系统修改采用 high，独立审查与验证按任务风险选择。最终合并、实际构建、原生回归和同条件测量由主 agent 完成。
