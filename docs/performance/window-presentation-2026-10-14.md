# 启动交接与统一 Loading 验证

> 历史记录：本页数据与命令对应当时的 Electron 实现。该实现、构建配置和测试入口现已移除；保留原始测量，不作为当前 Tauri 或 Chromium renderer 的验收结果。当前验证范围见[质量检查](../quality-gates.md)。

本轮保留 splash 的视觉与文档笔画动画，将三行笔画和光标抽成共享组件。异步内容区复用这套 Loading，按钮保存等短动作继续保留紧凑状态反馈。没有新增运行时依赖。

## 主窗口呈现

原先仅依赖约 120ms 的原生透明度淡入。实际开发启动记录还证明：Chromium 的 visible 状态可能早于系统窗口的 show 事件，按 visible 计时会让内容动画提前播放。

现在先等主窗口实际 show，再退出 splash。splash 的 closed 事件到达后，通过命名 preload 接口 `window.onPresented` 通知 renderer。通知会在 preload 缓存，避免早于 React 订阅时丢失。renderer 同时满足工作区 interactive、激活、可见及原生呈现后，等待 160ms，再执行 260ms 的透明度和 6px 位移动画。没有新增就绪等待，也不锁输入；窗口原生尺寸和位置不变。

系统减少动态效果或应用关闭面板动效时，不执行这段等待或动画。首次呈现完成后移除动效类、计时器、观察器和订阅；文件切换、重新聚焦或组件重新挂载不会重复播放。动画正常以 animationend 清理，1000ms 仅作为异常清理上限。

## 实际 Electron 记录

`e2e/performance/startupHandoff.performance.spec.ts` 使用隔离用户数据、真实原生窗口，不使用会主动 show 窗口的普通 E2E harness。两种模式分别使用构建产物和实际 Vite 开发中间件。测试在主入口加载前观察隐藏主窗口及可见 splash，随后核对原生事件、内容动画 start/end、编辑器 ready 及原生 bounds。

| 模式          | 主窗口 show 至 splash closed | splash closed 至内容 animationstart | animationstart 至 animationend |
| ------------- | ---------------------------: | ----------------------------------: | -----------------------------: |
| 构建产物      |                        163ms |                               191ms |                          258ms |
| Vite 开发模式 |                        176ms |                               200ms |                          258ms |

两条启动路径均通过，主界面动画在 splash 完全关闭后播放。两种模式的初始、最终原生 bounds 一致。事件时间包含调度和帧边界，CSS 声明时长为 260ms；这是本机 macOS 样本，不作为各平台性能基准。截图和原始事件记录保存在被忽略的 test-results 中。

## 组件与构建

- `DocumentLoadingLines` 是共享装饰动画；`DocumentLoadingState` 提供单一、明确的读屏 loading 状态。
- 源码、差异、绘图、地图、全部页面、历史预览、发布和代码块编辑的内容 Loading 接入共享组件，错误、重试、取消和保存入口保持原有行为。
- 编辑器加载保留上一就绪内容和实时编辑，取消原先额外的准备阶段等待。焦点仅在编辑器原先拥有焦点时恢复；用户转向其他区域会取消恢复。
- splash 和 workspace opening 的独立 HTML 都作为 Vite 输入，共用 React 组件及样式。public 不再存放这些页面的手写脚本。
- logo 设计预览也使用独立 Vite 入口，通过 `build:design-preview` 输出 `.tmp/design-preview`，不进入桌面安装包。

开发环境修改 preload/main 后需要完整重启 Electron，单独的 renderer 热更新不会更新旧 preload。旧 preload 热更新期间有兼容回退，保持会话可用；精确交接时序在重启后生效。
